# A 股盘前环境与仓位决策系统设计规格

## 1. 文档状态

- 版本：`0.1.0`
- 状态：待业务方书面复核
- 盘前时区：`Asia/Shanghai`
- 正式报告截止时间：每个 A 股交易日 `08:50`
- 第一阶段目标：用可解释、可回放的量化规则，回答“今天是否允许出手、总仓位上限是多少、当前市场奖励哪类短线交易者”。

## 2. 背景与核心假设

本系统不预测个股价格，也不自动下单。第一阶段聚焦短线交易环境、市场风格和仓位权限，减少在退潮期继续交易造成的回撤。

四个核心指标不按普通指数理解，而按“前一批短线参与者在下一交易日是否获得溢价”理解：

| 指标 | 业务含义 | 直接决定 |
| --- | --- | --- |
| 昨日打首板表现 | 昨日首板参与者今日的平均溢价 | 首板套利模式是否匹配当前市场 |
| 昨日非 ST 二板表现 | 昨日二板参与者今日的平均溢价 | 二进三接力意愿 |
| 最近多板表现 | 高位连板股整体强弱 | 高位风险偏好和接力风险 |
| 昨日涨停表现 | 全部昨日涨停股今日的平均表现 | 整体短线赚钱效应 |

在交易日 `T` 的 `08:50` 生成报告时，只允许使用截至 `T-1` 收盘后已经完整形成的数据。此时“昨日打首板表现”等字段代表数据提供方在 `T-1` 记录的完整值，禁止使用 `T` 开盘后更新的同名字段。

## 3. 第一阶段范围

### 3.1 包含范围

1. 判断全 A 股短线环境：赚钱效应、修复或退潮。
2. 判断市场风格：首板套利、高低切、接力行情、混合或全面退潮。
3. 生成 A、B、C、D 四级开仓权限。
4. 同时控制账户总仓位上限和单笔开仓上限。
5. 汇总隔夜美股、主要外围资产和 `08:50` 前新闻的利好、利空及不确定影响。
6. 输出可能延续、可能转强、观察或可能退潮的板块排名。
7. 保存每日输入、配置、结论、证据及事后表现，支持历史回放和阈值校准。
8. 数据源未确定期间，通过标准接口和 CSV 示例数据运行。

### 3.2 不包含范围

1. 不识别分时第一波拉升、回踩或突破前高。
2. 不实现大单净流入、小单净流出等个股买点规则。
3. 不选择具体股票，不提供止盈止损规则。
4. 不连接券商，不执行自动交易。
5. 第一版不使用机器学习直接生成交易结论，仅保留训练数据和模型接口边界。

## 4. 系统输出

每日报告必须包含：

1. `marketEnvironment`：`PROFIT_EFFECT`、`RECOVERY` 或 `EBB_TIDE`。
2. `recoveryStrength`：仅在修复环境下取 `STRONG` 或 `WEAK`，其他环境为空。
3. `marketStyle`：`FIRST_BOARD_ARBITRAGE`、`HIGH_LOW_SWITCH`、`RELAY`、`MIXED` 或 `BROAD_EBB_TIDE`。
4. `permissionGrade`：`A`、`B`、`C` 或 `D`。
5. `action`：`ALLOW`、`CAUTIOUS`、`TRIAL_ONLY` 或 `FORBIDDEN`。
6. `totalPositionRange`：建议账户总仓位区间。
7. `singlePositionRange`：建议单笔开仓区间或上限。
8. `riskGate`：`RED`、`ORANGE`、`YELLOW` 或 `NONE`。
9. `sectorOutlooks`：排名前三的板块、判断类型、分数和证据。
10. `positiveFactors`、`negativeFactors`、`missingFields` 和 `confidence`。
11. 报告日期、截止时间、规则版本、配置版本和数据快照标识。

## 5. 核心规则

### 5.1 市场环境

四项核心指标分别记为：

- `F`：昨日打首板表现；
- `S`：昨日非 ST 二板表现；
- `M`：最近多板表现；
- `L`：昨日涨停表现。

第一版按以下顺序判断，先命中的规则生效：

1. 当 `F < 0`、`S < 0`、`M < 0`、`L < 0` 时，环境为退潮。
2. 当 `L > 0` 且四项中至少三项大于 `0` 时，环境为赚钱效应。
3. 其余组合统一归为修复，避免用信号冲突的数据强行判为赚钱效应。
4. 修复环境中，四项至少两项大于 `0` 时为强修复，否则为弱修复。

边界值 `0` 视为中性，不计入正值或负值数量。

### 5.2 市场风格

风格规则按以下优先级执行：

1. 全面退潮：四项均小于 `0`。
2. 高低切：`F > 2%`、`S < 0` 且 `M < 0`。
3. 接力行情：`S > 2%`、`M > 2%` 且 `F <= 2%`。
4. 首板套利：`F > 2%`、`L > 0`，且不满足高低切。
5. 其他组合：混合。

### 5.3 基础开仓权限

基础权限同样按以下优先级执行：

1. D 级：四项均小于 `0`。
2. A 级：`F > 2%`、`L > 2%` 且 `M >= 0`。
3. B 级：`0 <= F <= 2%` 且 `L > 0`。
4. C 级：不满足 A、B、D 的信号冲突、首板较弱或接力主导环境。

权限与仓位的第一版映射如下：

| 权限 | 行动 | 账户总仓位 | 单笔仓位 |
| --- | --- | --- | --- |
| A | 允许出手 | `50%～80%` | `20%～30%` |
| B | 谨慎参与 | `20%～50%` | `10%～20%` |
| C | 仅允许极强机会试错 | `0%～20%` | 不超过 `10%` |
| D | 禁止出手 | `0%` | `0%` |

仓位结果是风险上限，不构成必须把仓位加到上限的指令。由于第一阶段不选择个股，系统只输出限制，不生成具体建仓清单。

### 5.4 风险闸门

风险闸门优先于基础权限：

| 风险级别 | 结果 |
| --- | --- |
| 红色 | 权限强制调整为 D，账户和单笔仓位均为 `0%` |
| 橙色 | 权限最高为 C，账户总仓位最高 `20%`，单笔最高 `10%` |
| 黄色 | 基础权限下调一级，D 级不再下调 |
| 无重大风险 | 保留基础权限 |

正面外围信息或利好新闻最多将 C 级提升为 B 级，不能提升 D 级，也不能绕过红色或橙色风险闸门。该约束避免外围利好把明确退潮误判为赚钱效应。

红色事件包括已确认并直接影响 A 股正常交易或系统性风险的突发事件。橙色事件包括外围市场异常下跌、重大政策不确定性或高可信度行业级利空。黄色事件包括影响范围有限、方向尚未完全确认的风险。具体事件阈值通过配置维护，并在积累样本后校准。

## 6. 板块轮动规则

板块模块输出相对优先级，不承诺板块必然上涨。每个板块采用 `0～100` 分，第一版维度如下：

| 维度 | 权重 |
| --- | ---: |
| 相对全市场强度 | 25 |
| 板块内上涨家数占比 | 15 |
| 涨停贡献 | 15 |
| 成交额变化 | 10 |
| 强势持续性 | 10 |
| 盘前新闻催化 | 15 |
| 拥挤和退潮风险 | -10 至 10 |

板块判断类型：

- 延续：前一日强势、内部广度健康、成交未显著衰退且无强利空；
- 可能转强：相对强度改善并存在新增高可信度催化；
- 观察：正负信号冲突或数据可信度不足；
- 可能退潮：高位拥挤、广度下降、成交衰退或出现明确利空。

报告按板块分数从高到低输出前三名，同时保留所有板块的完整计算结果供复盘使用。

## 7. 数据字段设计

### 7.1 短线溢价快照 `MarketPremiumSnapshot`

| --- | --- | --- |
| `tradeDate` | 日期 | 指标完整形成的 A 股交易日 |
| `firstBoardPremiumPct` | 小数 | 昨日打首板表现百分比 |
| `secondBoardPremiumPct` | 小数 | 昨日非 ST 二板表现百分比 |
| `multiBoardPremiumPct` | 小数 | 最近多板表现百分比 |
| `limitUpPremiumPct` | 小数 | 昨日涨停表现百分比 |
| `source` | 字符串 | 数据提供方或 CSV 文件标识 |
| `collectedAt` | 时间戳 | 必须早于正式报告截止时间 |

### 7.2 外围行情 `ExternalMarketSnapshot`

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `symbol` | 字符串 | 标普、纳指、道指、中概、A50、汇率或商品代码 |
| `marketDate` | 日期 | 对应市场交易日 |
| `returnPct` | 小数 | 已完成交易时段的涨跌幅 |
| `sessionStatus` | 枚举 | `CLOSED`、`PARTIAL` 或 `STALE` |
| `source` | 字符串 | 数据来源 |
| `collectedAt` | 时间戳 | 采集时间 |

### 7.3 新闻事件 `NewsEvent`

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `eventId` | 字符串 | 全局唯一 |
| `publishedAt` | 时间戳 | 晚于截止时间的事件不得进入正式报告 |
| `title` | 字符串 | 原始标题，不保存访问令牌等敏感信息 |
| `eventType` | 字符串 | 宏观、监管、公司、行业、地缘或其他 |
| `sentiment` | 小数 | `-1～1` |
| `impactLevel` | 整数 | `1～5` |
| `confidence` | 小数 | `0～1` |
| `affectedSectors` | 字符串数组 | 受影响板块代码 |
| `sourceCount` | 整数 | 独立来源数量 |
| `isMajorRisk` | 布尔值 | 是否进入风险闸门候选 |

### 7.4 板块快照 `SectorSnapshot`

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `sectorCode` | 字符串 | 稳定板块代码 |
| `sectorName` | 字符串 | 中文展示名称 |
| `returnPct` | 小数 | 板块涨跌幅 |
| `breadthPct` | 小数 | 板块内上涨家数占比 |
| `limitUpCount` | 整数 | 非负 |
| `turnoverChangePct` | 小数 | 相对前一交易日成交额变化 |
| `relativeStrengthPct` | 小数 | 相对全市场等权收益 |
| `persistenceDays` | 整数 | 连续强势交易日数量 |
| `catalystScore` | 小数 | `0～100` |
| `crowdingRiskScore` | 小数 | `0～100`，越高越拥挤 |

### 7.5 决策报告 `PreMarketDecision`

除第 4 节全部输出外，还必须保存 `reportDate`、`generatedAt`、`cutoffAt`、`inputSnapshotIds`、`ruleVersion`、`configVersion` 和 `evidence`。证据项包含规则编号、实际值、比较阈值和对结果的影响。

## 8. 数据质量和异常处理

1. 四个短线溢价指标任一缺失、过期或日期不一致时，报告状态为 `INSUFFICIENT_DATA`，禁止出手并输出 `0%` 仓位。
2. 外围或新闻数据部分缺失时允许生成报告，但必须降低可信度并列出缺失项。
3. 输入格式错误、计算异常或配置版本不存在时，不得沿用上一交易日结论，统一安全降级为禁止出手。
4. 同一报告日期只能有一个正式版本；重复运行产生草稿，显式发布后替换正式版本并保留历史版本。
5. 每条结论必须可追溯到原始快照和规则，不允许只输出无法解释的自然语言判断。
6. 日志不得记录数据源访问令牌、账户信息或其他敏感内容。

## 9. 数据流与组件边界

1. 数据适配器把 CSV 或未来第三方数据转换为统一快照。
2. 校验器检查日期、截止时间、完整度和字段范围。
3. 环境分类器只读取四个短线溢价指标，输出环境、修复强度和风格。
4. 权限引擎根据四项指标生成基础 A～D 级。
5. 风险引擎读取外围和新闻事件，生成风险闸门及调整依据。
6. 仓位引擎把调整后的权限映射到账户和单笔仓位限制。
7. 板块引擎独立计算板块相对优先级。
8. 报告生成器汇总结果并保存结构化报告和中文摘要。
9. 复盘模块在收盘后补充真实市场表现和交易样本结果，不回写盘前输入。

各组件只通过明确的数据对象通信，数据采集失败不得被评分器静默转换为零分。

## 10. 待确认与校准参数

以下参数已有可运行的试运行默认值，但尚未通过历史样本证明有效：

| 参数 | 试运行默认值 | 校准方式 |
| --- | --- | --- |
| A 级首板阈值 | `> 2%` | 使用约 50 笔历史交易分箱比较胜率和收益 |
| A 级涨停阈值 | `> 2%` | 比较阈值上下环境的最大回撤和平均收益 |
| 接力明显强阈值 | 二板和多板均 `> 2%` | 对接力日人工标注并计算一致率 |
| 多板明显退潮阈值 | `< 0%` | 检查退潮提前识别率和误报率 |
| 黄色风险降级幅度 | 下调一级 | 比较风险日仓位模拟结果 |
| 新闻最低可信度 | `0.60` | 按来源质量和事后验证结果校准 |
| 板块输出数量 | 前三名 | 根据报告可读性和命中覆盖率调整 |
| 板块权重 | 第 6 节默认权重 | 使用滚动历史窗口校准，不在全样本反复拟合 |
| 数据完整度阈值 | 核心四项必须 `100%` | 保持安全约束，不参与收益优化 |

数据源、新闻来源清单、板块分类体系和重大风险事件词典尚未选定。第一阶段通过适配器接口隔离这些选择，不影响核心规则对象和测试数据格式。

## 11. 验证与验收

### 11.1 技术验收

1. 能从标准 CSV 输入生成完整盘前报告。
2. 报告包含环境、风格、权限、双层仓位、风险、新闻摘要、板块排名和逐条证据。
3. 截止时间后的任何数据不会改变正式盘前结论。
4. 相同输入和相同配置版本必须得到相同结果。
5. 核心数据缺失或异常时必须安全降级为禁止出手。
6. 核心业务逻辑单元测试覆盖率不低于 `80%`，覆盖正常、边界和异常场景。
7. 每日输入、配置和输出可完整回放。

### 11.2 策略效果验证

1. 将现有约 50 笔交易按 A、B、C、D 环境重新分类。
2. 分别统计胜率、盈亏比、平均收益、样本量和最大回撤。
3. 检验首板表现与单笔收益的相关性，但不把小样本相关性表述为因果关系。
4. 对比始终满仓、仅使用基础权限、叠加风险闸门三种仓位曲线。
5. 统计退潮提前识别率、退潮漏报率和非退潮误报率。
6. 使用按时间滚动的训练区间和验证区间调整阈值，禁止使用同一批数据反复调参后再宣称验证通过。

第一阶段只有在技术验收全部通过后才可进入历史效果评估。约 50 笔样本只能用于初步校准，不能据此承诺未来胜率。

## 12. 第一版实现边界

第一版交付为本地可运行的 Python 规则引擎、CSV 模板、结构化 JSON 报告、中文 Markdown 报告、单元测试和示例数据。自动联网采集、定时执行、网页面板、消息推送和机器学习属于后续独立阶段，需在数据源与部署方式明确后分别设计。
