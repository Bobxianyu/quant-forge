# 新闻分析小范围验证实施计划

目标：执行上一轮已确认的新闻结构化与证据审查验证，输出可复跑的旁路报告。

## 方案与边界

- 三条公开历史材料用于当前会话模型的两轮探索性分析；分别保存输入、提取结果和审查结果。
- 来源文本保存短摘录或明确标注的人工整理摘要，不声称已归档全文。
- 两轮来自同一会话，非独立盲评；预期标签由本次会话整理，不能报告独立模型准确率。
- 当前采集时间如实记录。历史新闻不是当时保存的数据，不用于历史交易回测。
- 纯 Python 程序验证字段、证据片段、来源去重、时间、新鲜度和审查绑定。
- 调用现有风险与仓位函数做单事件敏感性分析，以 C 为假设基础权限；不发布正式报告。
- 不引入第三方依赖，不更改现有模型、规则、正式 CLI 与配置。

## 执行步骤

1. 新增 `tests/test_newsPilot.py`：正常事件、重复来源、伪造证据、异常字段、超时、旧闻、
   审查拒绝与篡改绑定、C 至 B 权限变化、报告隔离和命令行异常。先运行并记录失败。
2. 新增 `src/quant_forge/research/newsReview.py`：校验与审查，输出可接受或待核验及具体原因。
3. 新增 `src/quant_forge/research/newsPilot.py`：离线回放、假设权限对照、JSON/中文 Markdown 报告。
4. 在 `data/research/news-pilot/` 保存固定输入和本次分析记录；保存两个角色的提示词。
5. 运行真实材料验证，单独列出语义观察和机械校验，不把自标注一致性当准确率。
6. 运行全部 pytest、ruff，检查新增文件 UTF-8 无 BOM、LF；补充使用说明及实测结论。

## 验收

- 无法核实的证据、失效审查、晚于截止时间或过期事件不得成为旁路可采纳输入。
- 同一公告转载按一个来源计数；置信度明确属于未校准模型意见。
- 记录输入/输出摘要、规则配置版本、计算耗时；模型耗时、费用无法取得时为 null。
- 测试覆盖率达到项目规定的 80%；正式流程无改动。
