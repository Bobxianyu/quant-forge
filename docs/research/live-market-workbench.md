# 真实行情工作台

## 功能与启动

工作台提供四项真实指数、沪深 A 股行情、昨日及今日成交额、行业与概念归属。
打开页面读取本地已有快照，点击“刷新行情”才访问上游；没有数据时显示缺失，不填演示值。

```powershell
python -m pip install -e ".[web,dev]"
python -m quant_forge.web.app --port 8765 --data-dir outputs/market
```

浏览器访问 <http://127.0.0.1:8765>，在启动终端按 Ctrl+C 停止。
采集中关闭会等待当前任务结束，以免中断文件写入。
使用同一数据目录时只运行一个服务进程，不使用多 worker 模式。
服务仅绑定本机，不用于公网部署。

API Key 使用 `HITHINK_FINANCE_API_KEY` 环境变量；Windows 同时支持读取系统级环境配置。
密钥仅在发起采集时读取，不写入页面、快照或日志。缺少密钥仍可浏览已有快照。

## 页面口径

- 四项指数固定为 `883994.TI`、`883997.TI`、`883410.TI`、`883900.TI`。
- 涨跌幅使用供应商百分数原值；`1.5` 显示为 `1.50%`。
- 股票成交额以元保存，以亿元展示；默认昨日成交额降序，门槛默认为零。
- 昨日指采集当天之前最近一个交易日；休市日不把上一日累计成交额显示为今日成交额。
- 上游股票行情只提供整页最新时间，不代表每只股票的最后成交时间。
- 交易状态统一标为未核验；空值与真实零值分别显示。
- 行业与概念允许多个归属，以本次板块采集时点为准，不能用于倒填历史归属。
- 最新行情不生成交易权限或仓位结论，也不回写现有正式盘前报告。

## 快照与失败恢复

数据目录中三个模块分别为 `indices`、`sectors`、`stocks`。
每个模块的 `history/<唯一标识>.json` 保存采集结果、原始响应、来源和时间，历史不覆盖。
`latest.json` 原子切换到完整成功版本，并记录最近尝试时间及失败状态。
浏览器接口不返回原始响应，也不直接公开数据目录。

各模块独立更新，个股整批切换。一个模块失败时保留其旧快照，并继续采集其他模块。
网络恢复后再次点击刷新即可重试；历史日 K 缓存在 `cache/<交易日>/`，可跨重启复用。
损坏的日 K 缓存会重新请求；快照损坏仅在对应模块显示读取错误，可重新采集恢复。
首版不自动删除历史，也不提供历史浏览，磁盘占用随采集次数增长。

历史成交额优先读取官方最近 10 个交易日的全市场 Parquet 文件，使用锁定版本的 PyArrow 解码。
必须校验目标交易日、未复权、人民币、日线及记录唯一性；保存原文件、SHA-256 和脱敏元信息。
下载临时签名地址仅在内存使用；下载请求不携带 API Key，也不跟随到其他域名。
若批量文件不可用，则回退逐股历史日 K，并在页面明确展示历史来源。
板块、指数和股票模块独立采集，较慢的模块不会阻塞其他模块发布。
单模块内采用顺序请求和限流退避，不承诺实时逐笔更新；后续同交易日可复用昨日成交额缓存。
首次采集所有板块成分或逐股回退仍可能耗时较长。
供应商分页失败、重复记录或异常业务码不会被默认为成功数据。

## 本地接口

| 接口 | 说明 |
| --- | --- |
| `GET /api/session` | 获取本地防伪令牌 |
| `GET /api/market` | 读取各模块最新快照、错误和刷新状态，不采集 |
| `POST /api/market/refresh` | 携带 `X-CSRF-Token` 启动后台采集；已有任务返回 409 |

浏览器每隔一段时间读取正在运行的任务状态，这不是定时自动采集。
刷新请求只允许同源页面及合法防伪令牌；页面使用文本方式呈现上游名称和代码。
