# 新需求与现有系统迁移分析

分析日期：2026-10-18。

本文依据 [新需求分析](../../新需求分析.md) 与当前工作区源码，记录需求差异、复用边界和实施建议。
本文是需求影响分析，不是已经批准的实施规格；建议项和待定参数不能直接成为生效交易规则。

## 一、需求基线与已确认事项

### 1. 本轮直接确认

- 用户确认：继续在当前仓库开发独立系统，复用现有行情和研究基础。
- 用户确认：首版交付完整流程的最小闭环，覆盖情报、双周期、机会、策略评估、两道闸门和行动清单。
- 用户确认：首版接入真实新闻来源和 AI 服务，支持主动发现机会；缺少数据或参数的能力明确标记未就绪。
- 新需求作为后续设计的业务输入；旧版盘前引擎、首板观察预设不再代表完整产品目标。
- 原需求文件保留原文。本文补充的确认记录优先于原文中“使用方式尚未确定”的历史状态。

### 2. 新文档明确提出的目标

- 面向 A 股，覆盖信息勘测、机会发现、环境判断、选股、策略评估、开仓权限及动态跟踪。
- 产业逻辑与资金走势交叉验证，情绪周期与趋势周期分别评估。
- 依次验证产业与题材、板块与资金、个股与买点。
- 四类机会全部纳入目标范围；四种策略独立运行、分别评分，再由统一决策层处理。
- 分开输出机会质量、买点成熟度和开仓权限，允许没有机会、观望或空仓。
- 重要结论保留数据、证据和时间，历史验证避免使用决策时点之后的信息。

### 3. 仍需确定

- 首版范围内各模块的具体验收条件和实施顺序。
- 新增新闻、海外、资金及分时数据源，以及现有数据源对新字段的实际覆盖。
- AI 服务提供方式、分析频率、费用约束与失败处理。
- 策略筛选、入场、退出、失效的明确条件及数值口径。
- 双周期状态、S/A/B/C 环境等级的指标与阈值。
- 两项评分的分项、权重、缺失处理及启用条件。
- 账户风险输入、仓位上限、单笔和单日限制、连续亏损暂停及板块集中度规则。
- 定时运行、持续监控、提醒渠道和数据保存方式。

上述事项属于产品或交易规则选择。不能通过沿用旧默认值、演示数据或主观补值代替确认。

## 四、需要重新设计的业务边界

### 1. 四类机会与四种策略分别建模

| 机会分类 | 策略分类 |
| --- | --- |
| 新题材启动 | 大单资金模式 |
| 已有主线延续 | 主线趋势回调 |
| 主线趋势回调 | 龙头二波 |
| 龙头二波 | 新题材先手机会 |

上表仅列两组各自的类别，不表示逐行对应。
建议分别使用 `OpportunityType` 与 `StrategyType`，允许一个机会被多个策略评估。
“已有主线延续”不能因没有同名策略而被遗漏；“大单资金模式”也不能冒充独立机会分类。

### 2. 环境等级、策略信号、权限与行动状态分开

- 情绪周期：描述短线赚钱和亏钱效应及其变化。
- 趋势周期：描述指数、板块和个股的趋势结构。
- 环境等级：S/A/B/C，对两套周期及主线条件进行规则化综合，具体规则待定。
- 策略结果：对应策略是否成立、缺少什么确认、如何退出和何时失效。
- 开仓权限：两道闸门的独立结论及阻断原因。
- 行动状态：重点跟踪、等待确认、符合开仓条件、暂时排除。

旧版 `PermissionGrade.A/B/C/D` 是权限等级，新版 S/A/B/C 是环境等级。
不能仅将旧 A 改为 S、旧 D 改为 C；旧 B、C 与新 B、C 的字母重叠也不代表相同含义。

### 3. 两项评分不能替代权限

- 机会质量回答“是否值得研究”，买点成熟度回答“当前入场条件是否成熟”。
- 每种策略保留自己的评估和评分依据，统一层保留策略来源，不能简单相加获得更高权限。
- 缺少参数或证据时，建议显示“待配置”或“证据不足”，分数使用空值，不能冒充真实零分。
- 硬性阻断不能被高评分、新闻利好或多个策略同时命中抵消。
- 历史统计与评分不是上涨概率，也不自动构成可执行买点。

### 4. 数据时点贯穿整个分析链

保留现有快照及摘要追溯做法，增加各阶段的决策时点和输入可用时间。
事件发生时间、发布时间、首次采集时间、AI 分析完成时间和当前决策时间承担不同职责。

建议每次运行绑定 `runId`、`asOf`、交易阶段、输入快照、规则及配置版本、AI 研究记录。
盘后获知的材料、后来修订的数据和事后完成的 AI 分析不能倒填成盘前已知事实。
历史回放与实时运行必须能区分；旧 08:50 约束只适用于对应盘前阶段。

### 5. 统一风险需要账户输入

单笔风险、单日亏损、连续亏损和板块集中度依赖持仓、交易及账户状态。
仅有候选股票和行情不能证明这些条件满足；账户输入方式也是待确认事项。
同股命中多个策略应保留全部策略证据，并按同一证券合并执行机会，避免重复分配风险。
关联板块如何累计暴露和策略间如何共享预算仍需明确规则。

## 五、复用与替换建议

### 1. 优先复用

- 现有 Python 工程、FastAPI 本地服务和已实现的访问保护。
- `FuyaoClient`、`FuyaoCollector` 与 `DumpHistory` 的适配、校验及缓存基础。
- `SnapshotStore` 的历史保存和原子发布机制。
- 规则证据、配置合法性校验、输入及配置摘要。
- 新闻实验中的引文、来源和时间检查方法。
- 冻结研究输入、按时间分段验证、分离候选特征与事后标签的方法。
- 已保存数据、测试、失败研究结果和审计记录。

复用前按新契约核对覆盖、时效和时点，不能只因文件存在就视为数据条件满足。

### 2. 重新设计

- `PreMarketDecision` 为中心的单一业务结果和编排流程。
- 四项溢价直接决定整个市场权限的耦合关系。
- A～D 权限与旧固定仓位区间在新流程中的使用方式。
- 以首板观察预设代表完整选股产品的设计。
- 只显示行情表格的主要工作流，以及缺少持久化状态的观察名单。
- 仅覆盖旧盘前结论的报告结构。

### 3. 新增能力

- 事件、题材、产业链、公司关联证据与机会生命周期。
- 双周期评估、三层选股、四个独立策略及两项评分。
- 两道闸门、风险预算及策略重叠处理。
- 分阶段运行、观察跟踪、结构化每日报告和相应历史查询。

旧入口是否保留兼容、何时停止维护，应在正式迁移规格中决定；本轮不移除旧接口或历史产物。

## 六、已知数据与研究限制

本节描述仓库已记录的能力和缺口。
本轮额外核实了真实快讯及 DeepSeek 模型、搜索、抓取能力，见 [服务检查](serviceReadiness-20261018.md)。
以下历史资格、策略资金及分时等缺口，不因新闻接入验证通过而消失。

1. 当前采集器没有提供完整的大单、小单、主动买卖及回踩突破所需分时输入。
   大单资金策略必须先明确数据窗口、单位、分类方法和接口实际覆盖。
2. 正式行情界面对交易状态统一标记未知，不能据此认定已完成 ST、停牌或退市资格排除。
3. 当前板块成分不能用于倒填历史归属；业务关联度还需要公司业务和产业链证据。
4. 历史研究记录了证券覆盖不一致、历史资格和事件标签限制，已有面板不能直接承担全市场回测。
5. 新闻实验不是已验证的持续信息勘测系统，证据片段存在也不等于产业推断正确。
6. 旧权重研究中存在没有合格候选的结果，不能因为本次需求变化就将某组旧权重当成新策略默认值。
7. 新风险预算依赖账户状态，缺少输入时不能显示“预算校验通过”。

## 七、实施路径建议

推荐在当前仓库建立新的决策流程，逐步接入可复用底层，再分批替换旧流程。
直接向旧 `build_pre_market_decision` 叠加全部逻辑，会继续受固定截止时刻和旧权限模型约束。
一次性替换所有模块则会使数据问题、业务规则问题和界面问题同时出现，增加验收难度。

用户已选择完整流程的最小闭环。以下为交付拆分建议，不代表已经批准具体架构或开始实施：

| 阶段 | 目标与产物 | 验收重点 |
| --- | --- | --- |
| 1：业务契约与数据盘点 | 确定运行阶段、证据、双周期、机会、策略、评分、权限和行动结果的独立契约 | 概念不混用；未知项可表达；列出数据及参数缺口；明确四策略目标范围 |
| 2：情报与环境 | 接入有来源的情报与行情，输出双周期和主线研究结果 | 证据与时点可追溯；缺少条件时不编造评级；支持离线确定性回放 |
| 3：机会与策略 | 三层筛选、四类机会、四策略独立结果及两项评分 | 每个策略独立验收；缺少资金或阈值时保留未就绪状态；策略重叠可识别 |
| 4：统一权限与工作台 | 两道闸门、账户风险输入、四种行动状态、观察名单及报告 | 高分不能绕过硬规则；同股不重复分配风险；无合格机会有明确原因 |
| 5：日内运行与验证 | 盘前、开盘后、10:00、盘后更新，按确认范围增加调度和提醒 | 阶段可关联、运行不重复、过期数据可识别；分策略统计且避免未来信息 |

首版采用完整流程的最小闭环，必须明确其中哪些能力真实接入、哪些因条件不足未就绪。
真实新闻采集和在线 AI 研究属于首版范围，不能仅以手工导入材料或固定模型输出冒充已完成接入。
四种策略具备可调用接口和缺失提示，不等于四种策略已经实现并通过业务验收。
缺少退出条件、预算、必要数据或规则参数时，建议统一层不给出“符合开仓条件”；此为待确认设计建议。
后续若分批启用策略，需记录每个策略的可用状态和验收范围，不能声称四策略已经全部完成。

本次目标仍是研究与决策辅助。券商连接、自动下单不是原文已经确定的功能范围。

## 八、正式实施前需要写入规格的验收条件

- 两套周期分别输出，冲突时有明确处理，不能用单项溢价替代全市场判断。
- 每条机会包含来源、时间、影响路径、证据、不确定性及后续确认条件。
- 同一证券可保留多个策略结果；执行机会和风险分配按证券及相关暴露去重处理。
- 机会质量、买点成熟度和开仓权限分别存储，硬性拒绝优先。
- “重点跟踪”“等待确认”“符合开仓条件”“暂时排除”有明确的生成和转换规则。
- 无候选、没有合格买点、数据不足、参数未就绪、风险禁止分别记录原因。
- 所有分析使用当时可得的数据；新闻更新、AI 输出及账户状态同样受时点约束。
- 新策略先写测试再实现，覆盖正常、边界、异常、数据缺失和禁止规则，核心覆盖率至少 80%。
- 回测协议先冻结，使用按时间划分的验证集；交易收益还需费用、成交、退出及持仓规则。
- 自动运行与提醒只按最终确认的频率和渠道启用。

本轮完成需求阅读、当前实现核对及最小服务验证，未改变程序行为或启动常驻采集。
