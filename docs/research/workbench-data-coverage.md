## 一、结论与界面现状

同花顺 Fuyao 文档包含 A 股个股数据，足以规划代码、名称、行情、成交额及板块浏览。
现有前端可保留布局，但其完整筛选与本模式盘中触发条件尚不能仅靠已确认接口支撑。

实际检查文件：

- `docs/design/Workbench.html`：今日盘前、选股、数据中心、历史、规则设置五页原型。
- `docs/design/stockScreen.js`：`STOCK_SAMPLES` 为七个虚构样本；
  `getStockChecks` 筛选名称、板块、优先板块、昨日未涨停、成交额及状态；
  `renderStockScreen` 只读取样本；`STOCK_WATCHLIST` 为内存集合。
- `docs/design/workbench.js`：静态详情及操作说明，未连接真实行情或应用接口。
- 当前工作目录没有计划中的正式 `web/src` 页面和本地 Web 服务实现。

## 二、选股字段逐项映射

| 页面或契约字段 | 来源及处理 | 覆盖判断 |
| --- | --- | --- |
| 代码、名称、交易所 | `/api/meta/tickers/list?asset_type=a-share` 的 `thscode/name/exchange` | 有文档接口 |
| 名称/代码搜索 | 本地已缓存代码表，或 `/api/meta/tickers/search` | 有文档接口 |
| 上市日期 | 代码表 `list_date` | 可为空，不能保证每只完整 |
| 最新价、涨跌幅 | `/api/a-share/prices/snapshot` 的 `last_price/price_change_ratio_pct` | 有文档接口 |
| 昨日收盘、成交额 | `/api/a-share/prices/historical` 的 `date_ms/close_price/turnover` | 指定昨日日期并验证完整性 |
| 昨日涨幅 | 冻结的昨日有效行情涨幅，或按明确收益口径计算 | 不用今日快照直接填昨日值 |
| 成交额下限与排序 | `turnover` 单位元，显示亿元时除以 100000000 | 可计算；原型默认门槛为 5 亿元 |
| 板块归属 | 指数目录加 `/api/a-share-index/constituents/ths-stock-list`，反向构建成员映射 | 可加工；接口只给当前成分 |
| 优先板块 | 项目板块评分结果，经真实板块代码关联 | 非 API 直接字段；评分部分输入仍缺 |
| 昨日是否涨停 | 明确昨日日期的完整涨停池 | 有条件可派生；需验证覆盖范围及分页完整性 |
| 风险警示 | 涨停池有 `is_st`，但只覆盖池内股票 | 全市场字段未确认，不能支持完整排除 |
| 停牌与退市 | 已核对的代码表及价格字段没有完整对应状态 | 缺口；零成交或空值不能当作权威状态 |
| 采集时间、来源、快照 ID | 后端实际采集时记录及生成 | 项目负责，不能拿行情日期冒充采集时间 |
| 观察名单、筛选依据 | 应用服务保存选择及规则命中结果 | 不依赖额外行情，持久化尚未实现 |

历史收益计算须记录复权口径，不能混用前复权收盘与未复权前收；
普通收盘比值也不保证在除权日等同于行情商涨跌幅。
涨停池未返回某股票，只有在目标市场覆盖、当日数据就绪和分页完整均已验证后，
才可用于推断“不在该日涨停集合”；网络失败或缺页必须保留未知。
不得将股票名称不含 ST、交易量大于零或 `end_date=null` 当作交易状态全面正常的证明。
当前成分只能用于对应时点，历史筛选需保存当时成分，不能倒填。

## 三、其他页面能否支撑

| 页面 | 可复用部分 | 尚需完成 |
| --- | --- | --- |
| 今日盘前 | 现有引擎可计算环境、权限、仓位并给证据 | 四项表现真实序列和口径、外围及新闻输入、完整板块评分输入 |
| 数据中心 | 文件类别与校验结果展示 | 真正导入/采集服务；个股输入独立于现有四类 CSV |
| 历史报告 | 当前 CLI 有历史输出基础 | 运行查询、冻结输入、发布关联接口 |
| 规则设置 | 默认配置和版本可由现有配置提供 | 只读服务及前端绑定；不是行情供应商提供的仓位 |

首页四项表现不能用四只普通股票或四个任意指数替代。
板块广度与成交额变化可以计算，催化和拥挤评分则需另外定义输入和算法。
外围行情与新闻风险不能因缺少来源而展示为已经核实的“无风险”。

## 四、与实际交易模式的差距

当前 `getStockChecks` 仅做盘前观察筛选，不实现大单净流入、小单净流出、主动买卖或回踩突破。
“昨日未涨停、成交额不少于 5 亿元、优先板块”不能等价为模式买点。

- 主力资金文档明确暂未开放外部接入，不能把已展示的接口路径当作可调用能力。
- 高频动向同样暂未开放外部接入，且返回动向指标，不是原始分钟 OHLC。
- 主动买卖、盘口和足够精度的分时价格成交序列仍需独立数据源确认。
- 08:50 基线与当天盘中信号分开保存，历史图不能使用事后数据伪装实时判断。

## 五、建议的实施顺序

1. 先小范围实测代码表、单股票日 K、单板块成分与指定日期涨停池，核对账号权限与字段。
2. 实现后端采集和标准化，浏览器通过本地服务取数；API Key 留在后端。
3. 先交付真实个股浏览、成交额筛选、排序和观察名单，显示数据日期与字段覆盖情况。
4. 在完整交易状态未补齐前，标记“状态未核验”，不宣称已排除全部风险或输出可用交易候选。
5. 核实四项表现并连接环境报告，再按独立任务补充盘中买点；每个任务按 TDD 验收。

本次仅新增本核对文档；未修改界面、交易规则或配置，未运行界面交互测试或真实行情联调。
